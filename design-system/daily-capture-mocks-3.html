What this batch covers

Photo review (8) is the gap between shutter and commit. The capture is already in captures with dirty=1 the moment the shutter fires — this screen just lets the user enrich it before the row settles. "Save without caption" is intentional: it commits the row as-is and dismisses, because the speed-over-thoroughness path is what makes daily journaling actually happen.

Scan + OCR overlay (9) is the visible payoff of the fts_capture_text trigger. Each line is tinted by its OCR confidence so the user knows where the OCR is rough and worth fixing. Tapping a tinted line opens an inline editor that writes a capture_revisions row — preserving the original text in case the edit is wrong. Search results from set 2 mock 7 are the surface where this content reappears.

Capture detail (10) is reachable from any photo tile anywhere — Daily Log, Page detail, NotepadEntry editor, Search. The breadcrumb pill at the top tells the user where back leads, which matters because the deep-link entry path may have rebuilt the parent stack synthetically. Edit / Share / Move / Delete map onto the four highest- frequency actions on a single capture; everything else lives behind the kebab.

Conflict resolver (11) implements OPEN_QUESTIONS §10: two options, no merge UI. The diff highlights show the user exactly what differs without asking them to read both versions in full. "View all conflicts (4)" routes to the aggregated list from OPEN_QUESTIONS §12 for batch resolution. The local edit survives in conflict_stub until the user decides — there is no destructive write before that tap.
