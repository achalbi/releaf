Where each mock lands in the spec

Empty Today (4) covers the cold-launch experience the first mock didn't show — what the user sees before any capture exists for the day. The dashed prompt card replaces the inline editor when there's nothing yet, so the FAB and three quick-pills are the only things above the fold. This is the state that makes the "first keystroke commits to a real row" decision visible — there's no "creating entry…" intermediate.

Voice recording (5) is the most novel gesture in docs/DAILY_CAPTURE_UX.md §2.4: long-press on the Leaf FAB starts recording without opening the QuickCaptureSheet. The dim veil + pulsing FAB + live waveform make the recording state unmistakable; "slide up to cancel" gives a panic-out for accidental holds. Release transcribes and commits.

Calendar (6) is retrieval handle #1 from §4.1. Density dots per day are color-coded by capture kind so a power user can scan a month and spot the busy days at a glance. Today gets a coral ring even when empty (it always exists thanks to findOrCreate). The "Jump to today" pill makes long backward scrolls cheap to abandon.

Search (7) is retrieval handle #2 from §4.2. Results group by FTS5 source table — fts_notepad_notes, fts_capture_text, fts_page_body, fts_task_title — so the user sees a "by-kind" mental model instead of a flat list. Voice transcripts and scan OCR text both contribute to fts_capture_text, which is why a 0:42 voice memo can hit on the word "heron" without any explicit tagging.
