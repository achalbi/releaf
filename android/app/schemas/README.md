# Room schema snapshots

Auto-generated by Room's KSP processor on every build. One JSON file per
`@Database` version per entity-set, under:

    app/schemas/<fully-qualified database class>/<version>.json

These files are our only source-of-truth record of what each schema
version actually looked like. When you write a new `Migration(oldVer,
newVer)` in `ReleafDatabase.kt`, Room's in-memory migration test runner
diffs the post-migration state against the JSON at `<newVer>.json` and
fails the build if they diverge.

**Commit these.** They're generated but they function as a migration
contract — a change here is a change in the on-disk schema and needs to
travel with the code that produced it.

**Don't hand-edit them.** Bump `@Database(version = X)`, write the
migration, and let the next build regenerate the snapshot.
