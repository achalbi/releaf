What this prototype does and doesn't claim

This is a visual stitch, not a full functional spec. It's intended to let you and the team look at the merged composition and react before any QuickCaptureSheet.kt changes land. Three things are happening at once — pulling them apart for clarity:

1 · Layout merge

The "What arrived?" serif title from screenshot 1, the mustard Scan hero from screenshot 1 + 2, and the "or capture differently" small-tile row from screenshot 2 are stacked into a single full-height bottom sheet. Day | Recents lives at the top of the sheet (above the title) so it's reachable with the thumb without scrolling. The Home header pattern (TUESDAY · April 28 · search + calendar) stays visible above the scrim — it's not part of the sheet, it's the page underneath.

2 · Mode-set pivot from v1

v1 of this prototype put all capture modes on equal footing in a 2×3 tile grid. v2 promotes Scan to a hero with category pre-tagging and demotes the other five (Photo · Voice · To-do · Contact · Place) to a secondary row. This is a substantive editorial choice: it bets that document scanning is the highest-value, most-organizationally-fraught capture — receipts, medical records, school papers — and that pre-tagging at capture time saves the user from a separate filing pass. If most users actually open the app to write a note or take a photo, this hierarchy is wrong and the v1 grid is closer to right.

3 · Pre-tag categories ride existing tags

Concept Implementation Pre-tag categories Reuse tags table verbatim. The 6 tiles are just the user's 5 most-frequent tag_ids + an "add new" affordance. No new schema; the counts ("3 this week", "12 total") are live SQL aggregates. "Pre-tag" semantic Tap a category tile → open scanner with that tag_id pre-set on the not-yet-saved captures row. On save, the row is committed with kind='scan' + the pre-selected tag attached via capture_tags. Pre-tag is a UX shortcut, not a separate column. "3 this week" / "12 total" Both query capture_tags joined to captures where kind='scan'. "this week" filters by created_at >= datetime('now', '-7 days'); "total" is unbounded. "+ New tag" Same flow as Settings → Manage tags → New, returned to this sheet. Inline create keeps the user in the capture flow. Active-state highlight A pre-tag tile shows the letter-bg amber wash when it was the last category the user pre-tagged with. Heuristic, not a setting — gets out of the way after one capture. "Scan now" vs "Import" Scan now → ML Kit Document Scanner / VisionKit. Import → system file picker for an existing image or PDF, runs through the same OCR + crop pipeline. Both end at the same captures row.

4 · "Day | Recents" toggle

Day is what's shown — the capture surface. Recents is a flip of the same sheet to a list view of the last 10–15 captures across all kinds, with thumbnails / waveforms / first-line snippets. Tapping a recent item opens its detail screen; long-press re-uses it ("scan another receipt like this one"). Backed by a SELECT * FROM captures WHERE deleted_at IS NULL ORDER BY created_at DESC LIMIT 15 — no new tables.

5 · What's new visually

The mustard / saffron palette didn't exist in design-tokens.json. Adding it as color.scale.mustard.{50,100,500,700} + role tokens color.scan.{primary,deep,soft,tint} follows the same shape as the existing coral and green entries. The mustard shadow under the hero (0 8 22 rgba(178, 122, 42, 0.34)) is new — sister to shadow-fab for the coral FAB.

Open questions

1 · Is Scan really the right hero?
The whole prototype hinges on this. If the daily-capture user opens the app to write or photograph 80% of the time, Scan-as-hero is wrong and v1's equal grid wins. Recommend: instrument the existing v1 sheet for one release — count taps per mode — before committing to v2.
2 · Where do "the rest" of the captures appear when there's no scan intent?
Right now Photo / Voice / To-do / Contact / Place are visually demoted to a 5-tile row at the bottom. That's fine if Scan dominates, but feels punitive if a user is here for Voice. Consider: if the user has captured zero scans in the last 7 days, swap the hero to a Photo or Voice hero personalized by recency. A single "what arrived?" sheet that reshuffles based on usage.
3 · "What arrived?" + "Today's first capture" — too much?
The sheet has the serif title and the eyebrow inside the hero. Reads as two competing voices. Recommend: drop the eyebrow inside the hero; let "What arrived?" carry the framing, the hero just describes the action.
4 · How do pre-tag tiles handle a user with 30 tags?
Six tiles fits 5 + "new". Beyond that, options: a horizontal scroller after tile 5; a "More tags" drill-in that swaps the grid to a full list; or rank by recency-weighted frequency and clip to the top 5. Recommend: the recency-weighted top-5 — keeps the grid stable, surfaces the seasonal stuff ("medical" during a doctor visit week, "school" during back-to-school).
5 · Schema: is "scan category" the same as "tag"?
Treating them as identical (this prototype) means scans and notes share the same flat tag namespace. A user tagging notes with "travel" gets that tag available for scans too — usually fine, occasionally weird (you don't want "Letter" showing up as a tag suggestion on a hike photo). Alternative: add a scope column to tags with values scan | universal — costs one column, lets us filter the pre-tag grid to scan-scoped tags only. Recommend: ship without scope first; add it if real usage shows the namespace pollution.

Implementation footprint

One file changes meaningfully on each platform. Android: QuickCaptureSheet.kt swaps the LazyColumn-of-rows for: a Day/Recents tab row, a serif title block, a ScanHeroCard composable, a LazyVerticalGrid(GridCells.Fixed(3)) over the user's top-5 tags + an add tile, a divider row, and a LazyRow of the 5 alt-mode tiles. iOS: QuickCaptureSheet.swift mirrors with a LazyVGrid. Tokens: add a mustard ramp + scan role family to design-tokens.json; the pipeline regenerates the platform theme files. No SQL schema migration if we accept question 5's "tags are tags" answer.
